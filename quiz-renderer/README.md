# Quiz Renderer

Рабочее MVC-приложение, которое строит тест из объекта данных. Поддерживает один ответ, несколько ответов, «да/нет» и короткий текст; считает баллы, показывает разбор, сохраняет незавершённый прогресс и последние пять попыток.

## Запуск

```bash
cd quiz-renderer
npm start
```

Открыть [http://localhost:8080](http://localhost:8080). Тесты модели запускаются командой `npm test`.

## Архитектура: рассмотренные варианты

### Вариант 1 — три класса MVC

- `QuizModel` хранит вопросы и ответы, проверяет их и считает результат.
- `QuizView` создаёт DOM и передаёт события через обработчики.
- `QuizController` управляет текущим вопросом и связывает Model с View.

Это самый короткий и понятный вариант для учебного проекта. Минус: сохранение и дополнительные функции постепенно увеличивают Controller.

### Вариант 2 — MVC + отдельные сервисы

- Те же Model, View и Controller.
- `ProgressStorage` изолирует работу с `localStorage`.
- Источник вопросов остаётся обычным объектом данных и при необходимости может быть заменён API-репозиторием.

Этот вариант немного объёмнее, зато хранение можно заменить, не меняя модель и отображение. Он лучше масштабируется и проще тестируется.

### Выбранный подход

Использован второй вариант: Model ничего не знает о браузере, а View ничего не знает о правильных ответах. Controller организует жизненный цикл «рендер → ответ → переход → завершение» и остаётся единственным связующим звеном. Сохранение вынесено в `ProgressStorage`, потому что оно является инфраструктурой, а не правилом теста. Вопросы отделены от классов в `questions.js`, поэтому для нового теста достаточно заменить данные.

## Роли классов

- `QuizModel`: валидирует структуру теста, нормализует четыре типа ответов, хранит ответы, проверяет точное совпадение и формирует результат.
- `QuizView`: безопасно создаёт DOM через `textContent`, читает значения формы, обновляет прогресс, кнопки, результат и историю.
- `QuizController`: восстанавливает сессию, подписывает события, управляет индексом вопроса, запрещает переход с пустым ответом и завершает попытку.
- `ProgressStorage`: безопасно читает и пишет прогресс и историю; сбой `localStorage` не ломает тест.

## Примеры запросов к ИИ

**Проектирование Model**

> Спроектируй класс QuizModel для теста с вопросами single, multiple, boolean и text. Он должен хранить массив вопросов и ответы пользователя, нормализовать ввод, считать баллы и возвращать подробный результат. Предложи методы, формат данных, валидацию и поведение для пустых, неизвестных и устаревших ответов, но не связывай класс с DOM.

**Проектирование View**

> Опиши QuizView без бизнес-логики: методы рендера вопроса каждого типа, прогресса, навигации и результата, а также подписки на DOM-события. Учти доступность, восстановление выбранного ответа и безопасный вывод пользовательского текста.

**Связка через Controller**

> Покажи жизненный цикл QuizController для независимых QuizModel и QuizView: инициализация, восстановление, рендер, сохранение ответа, назад/вперёд, валидация пустого ответа, завершение и перезапуск. Model и View не должны ссылаться друг на друга.

**Добавление сохранения и статистики**

> В MVC-приложении Model хранит ответы, View работает с DOM, Controller управляет потоком. Добавь отдельный адаптер localStorage: сохраняй текущий индекс и ответы, безопасно восстанавливай только существующие вопросы, очищай прогресс после завершения и храни максимум пять результатов с датой. Ошибка хранилища не должна ломать основной сценарий.

## Ручная проверка

1. Ответить на каждый тип вопроса и проверить «Назад»/«Вперёд».
2. Перезагрузить страницу в середине — индекс и ответы должны восстановиться.
3. На последнем вопросе получить результат, баллы и пояснения.
4. Нажать «Пройти ещё раз» — ответы должны очиститься, история остаться.
5. Проверить клавиатурный фокус, hover-состояния и мобильную ширину.
